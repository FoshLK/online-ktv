# 基础架构说明

## 组件关系

```text
┌──────────────────────┐       REST / WebSocket       ┌────────────────────────┐
│ 用户桌面端           │◄────────────────────────────►│ NestJS API              │
│ apps/client          │                               │ apps/server             │
└──────────────────────┘                               ├────────────────────────┤
                                                       │ PostgreSQL：业务数据    │
┌──────────────────────┐       REST / WebSocket       │ Redis：在线及临时状态   │
│ 管理桌面端           │◄────────────────────────────►│ MinIO：音频/歌词/封面   │
│ apps/admin           │                               └────────────────────────┘
└──────────────────────┘
          │                            │
          └──── @ktv/ui / @ktv/contracts ────┘
```

用户端和管理端只发布为 Windows 桌面程序，不提供浏览器版本。Tauri 在安装包内嵌前端资源；开发期内部 Vite 服务仅监听 `127.0.0.1`。桌面端仅通过服务端访问业务数据，数据库密码、SMTP 授权码、对象存储密钥和管理员权限判断均留在服务端。

## 当前已落地

- 两个独立 Tauri 2 壳和 React 界面；开发时由 Tauri 在桌面窗口内调起本机 Vite 资源服务。
- 用户注册、QQ 邮箱验证码、Argon2id 密码、登录、令牌轮换/撤销和管理员角色守卫。
- NestJS 12 REST 服务和 `/rooms` Socket.IO 命名空间。
- Redis 可选运行模式：共享在线状态、带 TTL 的异常进程清理、Socket.IO 跨进程广播；未配置或连接失败时可回退到单进程内存模式。
- 房间创建、加入、退出、关闭、成员移除及容量/封禁校验；账号同时只能加入一个活跃房间。
- WebSocket 使用访问令牌识别用户，不接受客户端伪造的用户 ID；支持房内在线状态和服务器时钟采样。
- 播放准备会话冻结参与者名单，校验全员 SHA-256 后统一安排未来开始时间，并使用递增序列号拒绝过期上报。
- 后台真实概览、用户检索、停用/恢复和超级管理员角色变更；敏感用户变更写入审计日志。
- 后台活跃房间监管、成员强制移出、房间强制关闭、导入任务、播放记录及完整审计查询；强制操作会同步通知用户端并修正播放就绪屏障。
- 共享的房间、歌曲、播放快照与实时事件 TypeScript 契约。
- PostgreSQL Prisma 模型：用户、邮件验证、房间、成员、封禁、聊天、曲库、资产、歌词、导入任务、播放队列、同步会话和审计日志。
- PostgreSQL、Redis、MinIO 的本地 Docker Compose 配置。
- 无 Docker 环境可使用持久化 PGlite TCP 服务，已有迁移可直接部署并生成随机开发管理员。
- 本地对象存储、管理员歌曲上传/上下架、MP3/WAV 与 LRC 校验、SHA-256、Range 下载和导入审计。
- 用户 Tauri 原生下载缓存：临时文件、100 MB 上限、缓存复验、SHA-256 成功后自动上报房间就绪。
- 用户端本地音频播放器、LRC 时间轴、服务器时钟采样、统一定时开始和持续漂移校正。
- 房主/房间管理员可统一暂停、继续、跳转和停止；控制位置由服务器权威计算并按序列号广播。
- TypeScript 类型检查、生产构建和依赖审计脚本。

## 仍是边界占位的部分

以下接口目前只建立了结构，不代表业务已经完成：

- 登录限流、密码找回、设备会话列表及 Tauri 系统凭据库；
- Redis Sentinel/Cluster 高可用、运行中断线后的自动重连与反向代理多实例验收；
- MinIO/S3 生产驱动、分片上传和对象垃圾回收（本地存储与 Range 下载已经可用）；
- 歌曲导入器及外部工具进程隔离；
- 导入任务失败重试、人工复核队列、播放记录 CSV 导出和带签名的外部审计归档。

## 推荐实现顺序

1. 增加 MinIO/S3 驱动、对象清理、容量监控及生产备份。
2. 增加隔离的歌曲导入工作进程；外部工具失败不能影响主 API。
3. 增加设备输出选择、延迟校准与多台真实 Windows 电脑的同步验收工具。
4. 完成 EasyTier 节点服务化启动、TLS/反向代理、Redis 高可用与多机验收。

## 约定

- REST 路径统一以 `/api` 开头；实时房间命名空间为 `/rooms`。
- 数据库字段使用 UTC 时间；界面按用户时区显示。
- WebSocket 命令必须带递增 `sequence`，客户端忽略过期播放指令。
- 大文件不进入数据库；数据库只存对象键、大小、版本和 SHA-256。
- 管理端不因为 UI 隐藏而获得安全性，所有权限始终由服务端再次验证。
