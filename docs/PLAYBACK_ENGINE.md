# 桌面同步播放引擎（0.4.0）

## 时间轴模型

服务端是播放状态、序列号和位置的唯一权威来源。播放快照包含 `sessionId`、`sequence`、`startAtServerMs`、`pausedPositionMs` 和歌曲时长；客户端只上报观测位置，不以本地位置覆盖房间时间轴。

开始、继续和播放中跳转都会安排一个未来生效时间。客户端通过 Socket.IO 往返采样估算服务器时钟偏移，再换算为本机定时器时间。暂停位置由服务端按“基础位置 + 从开始时间经过的毫秒数”计算，因此房主无需提交可能已经漂移的本地位置。

## 客户端执行

1. Tauri Rust 层下载音频和 LRC，复验 SHA-256 后保存在应用缓存的 `songs/` 子目录。
2. Tauri `assetProtocol` 只开放 `$APPCACHE/songs/**`，播放器不获得任意文件系统读取范围。
3. 所有冻结成员报告资源就绪后，服务端广播同一个 `START` 时间点。
4. `<audio>` 在目标时刻定位到权威位置并播放；迟到或重连时根据当前服务器时间追赶，而不是从零开始。
5. LRC 解析器支持多个时间标签、1–3 位小数和全局 `[offset:]`，按当前播放位置二分查找歌词。

## 漂移校正

播放时每 250 ms 读取一次本地位置，每秒最多校正一次：

- 绝对漂移小于 45 ms：保持 1.0 倍速；
- 绝对漂移 45–250 ms：在 0.97–1.03 倍速内柔性收敛；
- 绝对漂移达到 250 ms：直接定位到权威位置。

客户端每 3 秒上报一次观测位置，服务端只接受属于当前会话、已经就绪且序列号相同的上报。上报当前用于诊断与后续延迟统计，不参与权威位置计算。

## 控制与恢复

房主、房间管理员和系统管理员可暂停、继续、前后跳转或停止。实时通道先广播定时命令，再广播对应快照，避免客户端在命令到达前提前执行新状态。命令包含会话与房间 ID，客户端只执行与当前快照相同序列号的命令。

重新加入房间时，即使错过了原始命令，客户端也能用快照中的开始时间和基础位置恢复。缓存仍存在但就绪确认在断线时丢失的情况下，客户端会重新发送幂等就绪事件。
